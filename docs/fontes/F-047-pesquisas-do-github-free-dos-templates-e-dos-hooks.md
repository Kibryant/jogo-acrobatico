## §1 — GitHub Actions, Godot 4.7.2 e gdUnit4 (agente general-purpose)

All eight topics are answered below. Each fact has its source URL and the date it was published or last updated. "Updated" for docs.github.com pages is the last commit to that page's source in github/docs; I looked those up through the GitHub API.

### 1. GitHub Free plan, private repos (Actions, Packages, Releases)

- **Included:** 2,000 minutes per month, 500 MB of artifact storage, and 10 GB of cache per repository. Larger runners cannot use the included minutes. Actions is free for public repos on standard runners and free for self-hosted runners. https://docs.github.com/en/billing/concepts/product-billing/github-actions (updated 2026-07-09)
- **Shared 500 MB:** confirmed. The docs say: "The artifact storage amounts shown are **shared** with GitHub Packages. This means your total storage across Actions artifacts and GitHub Packages storage cannot exceed the included amount for your plan." Overage costs $0.25 per GB-month for shared storage and $0.07 per GB-month for cache (same page). The pricing page lists "500MB of Packages storage" (https://github.com/pricing, no date shown).
- **Per-minute prices since 2026-01-01:** Linux 1-core $0.002, Linux 2-core $0.006, Windows 2-core $0.010, macOS 3/4-core $0.062. https://docs.github.com/en/billing/reference/actions-runner-pricing (updated 2026-07-09)
- **Multipliers: the exact rate not confirmed.** The current billing and pricing pages no longer contain a multiplier table or the word "multiplier". The Actions concepts page still says "For more information about minute multipliers, see GitHub Actions billing", and the link goes to the baseline minute costs price table (https://docs.github.com/en/actions/concepts/billing-and-usage). GitHub's Dec 2025 pricing page says free usage is consumed "based on list price the same way that Linux, Windows, and MacOS standard runners work today" (https://github.com/resources/insights/2026-pricing-changes-for-github-actions, dated 2025-12-15). No official source says whether a Windows minute now uses up 2 included minutes or about 1.67. Third-party sites disagree: https://cicdcalculator.com/github-actions says 2x and 10x; https://trimci.com/learn/github-actions-billing-explained/ (updated 2026-07-28) says the multipliers were folded into the per-runner rates.
- **Artifact retention:** default 90 days. Public repos can set 1–90 days and private repos 1–400 days. https://docs.github.com/en/organizations/managing-organization-settings/configuring-the-retention-period-for-github-actions-artifacts-and-logs-in-your-organization (updated 2026-09-15)
- **Cache:** 10 GB per repo by default, and admins can raise it as a paid option. "Repositories owned by users can configure up to 10 TB per repository." Entries not accessed in over 7 days are removed. The rate limits are 200 uploads and 1,500 downloads per minute per repo. https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching (updated 2026-09-10). Paid cache above 10 GB was announced at https://github.blog/changelog/2025-11-20-github-actions-cache-size-can-now-exceed-10-gb-per-repository/ (2025-11-20).
- **Release assets:** "Each file included in a release must be under 2 GiB. There is no limit on the total size of a release, nor bandwidth usage." https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases (updated 2026-07-08). Another page says each file must be smaller than your plan's Git LFS maximum file size, which is 2 GB on Free (https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github and https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-git-large-file-storage). Whether release assets count toward the 500 MB quota is **not confirmed**. No official text says they do, and the shared quota is defined as Actions artifacts plus Packages only.
- **2026 pricing changes:** announced 2025-12-16 at https://github.blog/changelog/2025-12-16-coming-soon-simpler-pricing-and-a-better-experience-for-github-actions/. Hosted runners became up to 39% cheaper on 2026-01-01; the new rates already include a $0.002/min "cloud platform charge". A $0.002/min charge on self-hosted runners was planned for 2026-03-01 but **postponed**: "We're postponing the announced billing change for self-hosted GitHub Actions…" (https://github.com/orgs/community/discussions/182186, 2025-12-17). I found no new date and no cancellation as of 2026-10-04 (not confirmed beyond that). The current docs say Actions is free for self-hosted runners.

### 2. `ubuntu-latest` moving to Ubuntu 26.04

- Ubuntu 26.04 became generally available on 2026-09-17. `ubuntu-latest` will move to it gradually **between 2026-10-19 and 2026-11-19**. https://github.blog/changelog/2026-09-17-ubuntu-26-generally-available-and-latest-migration/ (2026-09-17) and https://github.com/actions/runner-images/issues/14748 (created 2026-09-17). The issue says you can "Switch back to Ubuntu 24.04 by specifying the `ubuntu-24.04` label."
- **`ubuntu-24.04` is still supported, and I found no deprecation notice.** The README still maps `ubuntu-latest` to 24.04 and says "We support (at maximum) 2 GA images and 1 beta image at a time." https://github.com/actions/runner-images (updated 2026-09-17). endoflife.date lists its end of support as "Not yet specified": https://endoflife.date/github-actions-runner-images (updated 2026-09-24). The end date is not announced, so not confirmed.
- **For context, `ubuntu-22.04` is being retired.** Deprecation started 2026-09-17 and it becomes fully unsupported on 2027-04-17. Jobs will fail on purpose during brownouts on 2027-03-23, 03-30, 04-06 and 04-13, from 14:00 to 00:00 UTC. https://github.com/actions/runner-images/issues/14254 (created 2026-06-16)

### 3. Godot 4.7.2-stable export templates

- The release was published 2026-08-18. https://github.com/godotengine/godot-builds/releases/tag/4.7.2-stable and https://godotengine.org/article/maintenance-release-godot-4-7-2/ (2026-08-18)

- **No per-platform template assets exist in the release.** It has 34 files plus 2 source archives. Other assets you may use in CI: the Linux editor `Godot_v4.7.2-stable_linux.x86_64.zip` (77,860,424 bytes) and the Windows editor `Godot_v4.7.2-stable_win64.exe.zip` (86,013,866 bytes).

The 4.7 beta 1 post says it works by "retrieving slices of the bulk package itself" (https://godotengine.org/article/dev-snapshot-godot-4-7-beta-1/, 2026-04-24). Installing from a local .tpz file was added back by PR #118649, merged 2026-04-22 (https://github.com/godotengine/godot/pull/118649).

### 4. `chickensoft-games/setup-godot@v2`

- **Latest tag:** v2.4.3, published 2026-10-01. The floating `v2` tag points to the same commit (`ac93246e`). https://github.com/chickensoft-games/setup-godot/releases
- **`include-templates: true` downloads the full .tpz, not per platform.** The input is described as "True will also download the Godot Export Templates for each platform" and defaults to false (https://github.com/chickensoft-games/setup-godot/blob/main/action.yml). The code (`src/utils.ts`, last commit 2026-08-28) fetches `…_export_templates.tpz` from `github.com/godotengine/godot-builds/releases/download/…`. If `use-dotnet` is true, it fetches the mono templates instead; **`use-dotnet` defaults to `true`**. On Linux the templates are installed to `~/.local/share/godot/export_templates/<4.7.2.stable or 4.7.2.stable.mono>`.
- **Caching: yes.** The `cache` input defaults to true. `src/main.ts` saves and restores with `@actions/cache`; the key is the Godot download URL, with a `-no-templates` suffix when templates are off. The cached paths are the Godot install folder plus the unpacked templates folder (about 1.93 GiB unpacked for the full 4.7.2 set). The compressed size of that cache entry is not confirmed. The action runs on node24.

### 5. Windows export from a Linux runner

- **rcedit and wine are no longer needed.** Godot has edited the Windows executable's icon and version info itself since **4.5**: PR #75950, "Export: Modify Windows template without rcedit", merged 2025-06-05, milestone 4.5 (https://github.com/godotengine/godot/pull/75950). It removed the `export/windows/rcedit` and `export/windows/wine` editor settings. The 4.7 docs and the 4.7.2 Windows export source no longer mention rcedit or wine.
- **Export option:** `application/modify_resources`: "If enabled, icon and metadata of the exported executable is set according to the other `application/*` values." `application/file_version` and `application/product_version` fall back to `application/config/version` when empty. https://docs.godotengine.org/en/4.7/classes/class_editorexportplatformwindows.html
- **What can go wrong in 4.7.2** (from the 4.7.2-stable source): a bad icon produces the warning "Invalid icon file", and the icon is skipped. An explicitly set file or product version must have 4 integer parts and no `-`; otherwise you get "Invalid file version." or "Invalid product version." These are only warnings and do not block the export. When it falls back to `application/config/version`, a 3-part version is padded (0.1.0 becomes 0.1.0.0). If the project version contains anything other than digits and periods, it logs "Invalid version number … can only contain numeric characters (0-9) and non-consecutive periods (.)" and uses **1.0.0.0**.
- **Before 4.5** (4.4.1 source): a missing rcedit or wine produced a warning such as "Could not find rcedit executable…", and the export still succeeded. https://docs.godotengine.org/en/4.4/tutorials/export/changing_application_icon_for_windows.html

### 6. Dedicated server export in 4.7, and headless export bugs

- **Export mode "Export as dedicated server":** "the `dedicated_server` feature tag is automatically added to the exported project" and it "will also force `--headless`" when the exported game runs. Each resource can be set to Strip Visuals, Keep or Remove; the docs warn that Remove breaks scenes that reference the removed file. No separate server template is needed; since 4.0, any binary can run with `--headless`. A PCK-only server is also described: put the PCK next to a template binary with the same name. https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_dedicated_servers.html
- **Command line:** https://docs.godotengine.org/en/4.7/tutorials/editor/command_line_tutorial.html and https://docs.godotengine.org/en/4.7/tutorials/export/exporting_projects.html. `--headless` means `--display-driver headless --audio-driver Dummy`. `--export-release <preset> <path>` exports a release build. `--export-debug` uses the debug template and runs the import first. `--export-pack` writes PCK or ZIP depending on the file extension and also runs the import. The preset name must match `export_presets.cfg`, the path is relative to the project folder, the target folder must already exist, and the templates must be installed. A failed export returns a non-zero exit code since 4.3 (https://github.com/godotengine/godot/issues/83042).
- **Embed PCK:** `binary_format/embed_pck` exists for both Windows and Linux: "If `true`, project resources are embedded into the executable." On Windows, embedding works only up to about 3.89 GB for executable plus PCK.
- **Known 4.7.x export bugs:**
  - **#123712** (opened 2026-09-22, open, labeled confirmed and crash): the export finishes, then Godot crashes on exit with exit code 134 (a segfault on 4.7.2). It affects 4.6.3, 4.7.2 and 4.8-dev6 on Ubuntu 22.04.5. The title names AdMob and gdUnit4, but the reporter's minimal repro uses no addons. https://github.com/godotengine/godot/issues/123712
  - **gdUnit4 #1324** (opened and closed 2026-08-27): with gdUnit4 6.2.0 installed, Godot 4.7.2 crashes on the first command-line export when the `.godot` folder is missing, with "FATAL: Index p_index = 1 is out of bounds (size() = 0)". The maintainer's answer was "You need to exclude the plugin", pointing to https://github.com/godot-gdunit-labs/gdUnit4/discussions/650. https://github.com/godot-gdunit-labs/gdUnit4/issues/1324
  - **#119478** (opened 2026-05-15, open): since 4.7 beta 2, headless runs overwrite `editor_settings-4.7.tres` with defaults; a regression from 4.6.2. https://github.com/godotengine/godot/issues/119478
  - **Fixed in 4.7.1** (released 2026-07-14): "Fix incorrect per-instance shader parameters when exporting in headless mode (GH-120794)". https://godotengine.org/article/release-candidate-godot-4-7-1-rc-2/
  - **#123606** (opened 2026-09-18, open): exports since 4.6.1 include 4.8 MB of ICU data.
  - **#100465** (opened 2024-12-16, open, regression from 4.3): a headless export hangs when the project files have identical timestamps. Whether it still happens in 4.7 is not confirmed.
  - The 4.7.2 release notes list no fixes specific to exporting.

### 7. Project version and stamping a build id

- **`application/config/version` was added in 4.2** by PR #35555, "Add a 'version' project setting and use it in new export presets", merged 2023-08-04, milestone 4.2 (https://github.com/godotengine/godot/pull/35555). It is absent from `ProjectSettings.xml` at 4.1-stable and present at 4.2-stable. Its description at 4.7.2: "The project's human-readable version identifier. This is used by exporters if the version identifier isn't overridden there… the exporter will use `1.0.0`" when it is empty. At runtime you read it with `ProjectSettings.get_setting("application/config/version")` (https://forum.godotengine.org/t/how-to-read-app-version-number-at-runtime/53634).
- **Official override file:** "Any project setting can be overridden by creating a file named `override.cfg`… This can also be used in exported projects by placing this file in the same directory as the project binary." https://docs.godotengine.org/en/4.7/classes/class_projectsettings.html
- **Common ways to stamp a build id (all are addons that hook into export):** KoBeWi's "Auto Export Version" (https://godotengine.org/asset-library/asset/1430, updated 2024-04-15); "Git SHA Project Setting" (https://godotengine.org/asset-library/asset/1979, 2025-03-04); "godot-git-describe" (https://github.com/zibetnu/godot-git-describe). I found no official Godot doc describing a standard CI recipe beyond these.

### 8. gdUnit4

- **Latest release:** v6.2.1, published 2026-08-20. No newer tag or pre-release exists as of 2026-10-04. https://github.com/godot-gdunit-labs/gdUnit4/releases
- **Godot 4.7.2 is not listed** in the compatibility table, so support is not confirmed (https://github.com/godot-gdunit-labs/gdUnit4, README changed 2026-10-04). The table lists v4.5 through v4.7.1 plus v4.8.dev7 for master (v6.2.1).
- **CLI:** https://godot-gdunit-labs.github.io/gdUnit4/latest/advanced_testing/cmd/ (docs version v6.2.x). It writes HTML and JUnit XML (`results.xml`) reports; `-rd/--report-directory` sets the output folder (default `res://reports/`); `-rc/--report-count` sets how many reports are kept (default 20). **`-c/--continue` exists:** "By default GdUnit will abort on first test failure to be fail fast, instead of stop after first failure you can use this option to run the complete test set." Exit codes are 0 for all passed, 100 for failures and 101 for warnings. The runner scripts are `addons/gdUnit4/runtest.sh` and `runtest.cmd`, and they use the `GODOT_BIN` environment variable.

## §2 — Os hooks do Claude Code (agente claude-code-guide)

Based on my review of the official Claude Code documentation, here are precise answers to your 10 hooks questions. Where documentation is silent, I've marked it as "not documented."

1. **PreToolUse/PostToolUse JSON and file path fields** (https://code.claude.com/docs/en/hooks.md): the input carries `session_id`, `cwd`, `hook_event_name`, `tool_name`, `tool_input`, `tool_use_id` and, for PreToolUse, `permission_mode`; PostToolUse also carries the tool output. Edit, Write, MultiEdit and NotebookEdit pass `file_path` inside `tool_input`. Not documented: the `tool_input` fields of the other tools beyond Bash's `command`.
2. **How PreToolUse blocks a call** (hooks.md): return JSON on stdout with `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": "…"}}`. Exit code 0 with JSON: the decision applies; exit code 2: blocking error; other codes: non-blocking error. The reason appears in the transcript, and Claude reads it as why the tool cannot run.
3. **Bypass permissions mode** (https://code.claude.com/docs/en/permission-modes.md): "Deny rules and explicit ask rules apply in every mode, including bypassPermissions." A PreToolUse hook that returns `deny` blocks the call in bypass mode. A third-party issue tracker reports that a hook returning `ask` silently disables `permissions.deny` rules (https://claudeissues.com/issue/39344).
4. **Subagents** (hooks.md): hooks in the project `.claude/settings.json` fire for tool calls made inside subagents; the input includes `agent_id` and `agent_type`. Not documented: whether agent files in `.claude/agents/` can declare their own hooks.
5. **Matchers** (hooks.md): `"Edit|Write|MultiEdit"`; regex is supported. The `if` field uses permission-rule syntax such as `Edit(*.ts)`; a third-party report says `Edit(*.ts)` never fires because tools pass absolute paths (https://claudeissues.com/issue/49229). The hook script must read `tool_input` itself for complex filtering.
6. **Windows:** with Git installed, Git Bash runs hook `command` strings; without Git, PowerShell. No per-hook `shell` field is listed. `${CLAUDE_PROJECT_DIR}` resolves on all platforms; exec form with `args` is recommended on Windows; `.cmd` and `.bat` need exec form.
7. **PostToolUse** (hooks.md): it runs after the tool succeeded; a failing or timed-out PostToolUse hook does not undo the edit.
8. **Timeouts** (hooks.md): 600 s by default for command hooks, settable per hook with `timeout`. Not documented: whether several matching hooks run in parallel.
9. **Testing in a session** (hooks.md): `/hooks` opens a read-only list of the configured hooks with their sources; `claude --debug-file <path>` logs hook execution.
10. **Writes through Bash and the sandbox** (https://code.claude.com/docs/en/sandboxing.md): a PreToolUse hook on Edit or Write does not see Bash commands like `sed -i` or `cat > file`; protecting files against them needs a Bash hook that parses the command. "The built-in sandbox runs on macOS, Linux, and WSL2; it is not available on native Windows." On native Windows, the only file protection is PreToolUse hooks and permission rules.
